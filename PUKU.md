# PUKU.md

This file provides guidance to puku-cli when working with code in this repository.

## Project

LinguaMate is a Streamlit app that helps non-native English speakers craft natural, tone-adjusted responses. It calls the Groq API and renders three text variations plus nuance and pronunciation tips. Single Python entry point, no tests, no prior git history.

## Entry point

- Real entry point is `streamlit_app.py`. Run it with:
  ```
  .venv/bin/streamlit run streamlit_app.py
  ```
- `main.py` is a leftover from `uv init` and is not imported anywhere. Do not add code to it; do not delete it without checking first.

## Environment

- Python 3.11 (pinned in `.python-version`); dependencies managed by `uv` (see `uv.lock`).
- `GROQ_API_KEY` is resolved in this order: sidebar text input → `st.secrets["GROQ_API_KEY"]` → `os.environ["GROQ_API_KEY"]` (loaded from `.env` via `python-dotenv`). `.env` is gitignored — never commit it.
- Default model is `openai/gpt-oss-120b` with `llama-3.3-70b-versatile` as the fallback. The Groq call uses `response_format={"type": "json_object"}` and `call_groq()` tries the primary then the fallback.

## Streamlit best practices

Follow the rules in the bundled `developing-with-streamlit` skill (loaded automatically). The non-obvious ones for this repo:

- Sentence casing for titles and labels (no "Get Smart Suggestions" — use "Get smart suggestions").
- Material Symbols icons over emojis in widget labels (`:material/rocket_launch:`, `:material/translate:`).
- Never use `use_container_width`; rely on the default stretch or `width="stretch"`.
- The input form is wrapped in `st.form("linguamate_form")` so interim edits don't trigger reruns — keep new inputs inside that form.
- Slow API calls already live behind a `st.spinner` inside a reserved `st.container()` slot; preserve that pattern when adding new output sections.

## Prompt contract

The behavior of `SYSTEM_PROMPT` in `streamlit_app.py` is load-bearing for the helper logic in `has_example`, `find_missing_examples`, and `call_groq_with_examples`. When changing the prompt:

- Keep the JSON keys exactly: `professional`, `casual`, `direct`, `nuance_tips[]`, `pronunciation_hints[]`.
- Keep the rule that every entry in `nuance_tips` and `pronunciation_hints` contains a concrete example (parenthetical, quoted phrase, italicized token, or `e.g.`/`such as` prefix). The post-parse check in `find_missing_examples` regex-checks for these and triggers an auto-regenerate; if you weaken the rule, also update `has_example` and the regex constants.
- Keep `response_format={"type": "json_object"}` enabled; the parser calls `json.loads` directly on the model output.

## Tooling

- `ruff` is the configured formatter. Run manually with `.venv/bin/python -m ruff format <file>` or `uv run ruff format`.
- No tests yet. Before adding a test framework, confirm with the team — `streamlit_app.py` is small enough that a heavy framework is overkill.
- A `PostToolUse` hook in `.puku-cli/settings.json` runs `ruff format` on every `Write`/`Edit`; it is non-blocking, so do not rely on it to enforce style — review the diff.

## Gotchas

- `main.py` exists and looks like an entry point but is not — searches for "main app" should match `streamlit_app.py`.
- Streamlit reruns the whole script on every widget change. Avoid module-level mutable state; use `st.session_state` with stable widget `key` values.
- `streamlit_app.py` is a single-file script — keep it that way unless the file grows past ~500 lines. Above that, split helpers into `app/` per the Streamlit code-organization guidance.
- `__pycache__/` is generated by imports during smoke tests; it's already ignored by `.gitignore`.
